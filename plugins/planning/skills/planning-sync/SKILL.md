---
name: planning-sync
description: Reconcile existing planning documents with code, tests, and product decisions after changes or when inconsistencies are reported. Do not use to initialize a project without planning documents.
---

Read the project instructions and relevant planning, code and tests. Compare observable behavior, policies, architecture, screen descriptions and diagrams within the requested scope; identify evidence for each mismatch. A mismatch is an error to investigate, not an open question. Correct stale documentation when implementation and established decisions establish intent; fix implementation when the agreed specification is authoritative and the user authorized code changes. If the intended policy is genuinely undecided, present the specific policy choice rather than silently choosing it. Do not treat missing evidence as a policy choice.

Update related links and diagrams together, preserve unrelated decisions, and validate the affected behavior and document references. Report unresolved discrepancies with their evidence and limitations.
